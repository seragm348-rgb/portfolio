How I work

Fix the root cause, not the symptom

01

Diagnose before touching anything

Read the logs, the policy, the routing table. A change made before the fault is understood is just a second problem.

02

Design so it survives failure

Health checks, multi-AZ spread, least-privilege boundaries — reliability is decided at setup time, not during the incident.

03

Automate and write it down

If a fix only lives in my terminal history, it isn't finished. Repeatable steps and clear notes come with the work.

04

Verify, then hand off clean

Prove the fix with a test you can repeat, then leave the setup understandable to whoever owns it next.
